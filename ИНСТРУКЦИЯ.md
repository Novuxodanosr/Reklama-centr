# Reklama Centr — инструкция по проекту

Сайт: **https://reklama-centr.uz** · Instagram: **@reklama.centr.uz**
Полная история решений и правила заказчика — в [HANDOFF.md](HANDOFF.md). Читать перед любыми правками.

> Пароли и ключи в этом репозитории НЕ хранятся и храниться не должны.
> Они лежат у владельца (см. раздел «Доступы») и в локальном файле `.env.local`, который в git не попадает.

---

## 1. Что это за проект

- Сайт рекламно-производственной компании Reklama Centr (Ташкент), три языка: RU (`/`), EN (`/en`), UZ (`/uz`).
- Технологии: Next.js 14 (React), TypeScript, Tailwind, next-intl, framer-motion.
- На хостинге сайт работает **без Node.js**: собирается в готовые HTML-страницы, форма заявок — PHP-файл,
  адреса и защиту настраивает `.htaccess` (Apache).

## 3. Запуск на своём компьютере

1. Установить **Node.js LTS** (nodejs.org) и **Git** (git-scm.com).
2. Скачать проект: `git clone https://github.com/Novuxodanosr/Reklama-centr.git`
3. В папке проекта создать файл `.env.local` по образцу `.env.example` (значения — у владельца, см. «Доступы»).
4. Запуск: двойной щелчок по `ЗАПУСК-САЙТА.bat` (Windows) или в терминале `npm install`, затем `npm run dev`.
5. Открыть http://localhost:3000. Окно сервера не закрывать, пока смотрите сайт.

## 4. Как вносить правки

- **Текст** — найти фразу в `messages/ru.json` (и такую же в `en.json`, `uz.json`), поправить, сохранить. На localhost видно сразу.
- **Новая работа в портфолио** — фото (WebP, до ~1200 px) в `public/works/`, строка в `lib/works.ts`,
  подпись в `messages/*.json → works.items.<id>` на трёх языках. Работы в начале списка — показываются первыми.
- **Телефон / адрес / соцсети** — `lib/site.ts`. Почта, Telegram, Instagram: если поле `null`, кнопки на сайте скрыты;
  вписать адрес — кнопки появятся сами.
- Правила заказчика (что нельзя писать, какие цифры запрещены и т. д.) — в HANDOFF.md. Главное:
  только реальные факты; «расчёт за 15 минут» — только после запуска CRM; не писать «собственные бригады».

## 5. Как выложить изменения на сайт

1. Собрать: `node scripts/build-static.mjs` → появятся папка `deploy/` и архив `deploy.zip`.
   (В `deploy/api/config.php` сборка кладёт ключ Telegram-бота из `.env.local`.)
2. Войти в панель хостинга (см. «Доступы») → **Менеджер файлов** → `domains/reklama-centr.uz/public_html`.
3. **Загрузить** `deploy.zip` → правый клик → **Распаковать** (галочка «Merge and overwrite» включена).
   Если файл больше 10 МБ и загрузка не идёт — разбить на части (так делал Claude).
4. **Удалить архив** после распаковки — внутри ключ бота.
5. Проверить https://reklama-centr.uz.

Сайт ps.com.uz живёт на том же хостинге в своей папке `domains/ps.com.uz` — **его не трогать**.

## 6. Домены, хостинг, https

| Что | Где / как |
|---|---|

| Хостинг | webname.uz, тариф Brillant 1G, общий с ps.com.uz, оплачен до 05.05.2027. PHP + Apache, Node.js нет |

| https | Let's Encrypt в DirectAdmin → SSL/TLS, продлевается сам. Все адреса ведут на https://reklama-centr.uz |

## 7. Заявки и Telegram

- Форма на сайте → `api/lead.php` → бот **@rc_zayavki_bot** → группа «Менеджеры», тема «ЗАЯВКИ».
- Ключ бота: `TELEGRAM_BOT_TOKEN` в `.env.local` (локально) и `api/config.php` (на хостинге, закрыт от скачивания).
- Если ключ бота засветился — в Telegram у @BotFather: `/revoke` → новый ключ → в `.env.local` → пересобрать и залить.

**не** через чаты и не через этот репозиторий. После передачи — включить двухэтапную защиту везде, где можно.

## 9. Совместная работа через GitHub

- Владелец репозитория: GitHub → репозиторий → **Settings → Collaborators → Add people** → ник участника.
- Репозиторий должен быть **приватным** (Settings → General → Danger Zone → Change visibility → Private).
- Обычный цикл: `git pull` → правки → `git add -A` → `git commit -m "что изменил"` → `git push`.
- Сайт на хостинг **не обновляется сам** от пуша — после изменений нужно собрать и залить (раздел 5).
